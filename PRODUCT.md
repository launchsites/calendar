# Product

Calendar opens on today's Day view. Tap the date to return to today and press and hold it for Jump to Date, Previous and Next. Use the bottom view selector to change scale while keeping the selected date. Swipe horizontally to advance by the active interval. The date sits over a soft scroll-edge fade, with the Settings button in Liquid Glass. On iPhone, the text-only Day, Week and Month control uses a glass capsule with a sliding selection. The glass add action sits separately beside it. Settings opens to Profiles and links to Appearance, Calendar Display, Connections, Calendars, Quick Entry and Advanced. The accent colour applies to the year, add button and current-time line. Week lists events and scheduled tasks by day. Month uses a seven-column grid with event and task titles. On iPhone, tap or hold a date to preview its scrollable list, then tap Open Day for the full timeline. On Mac, click the overflow count to see the list.

Day groups visible all-day events above scheduled tasks under the date. Both compact strips loop when their items overflow and pause after a swipe. Turn off Auto-scroll tasks above Hide Tasks Banner to scroll tasks manually. Reduce Motion keeps both strips under manual control. The banner travels with its day during a page swipe, and the header fade stays fixed across both pages. Mark an event important from its details or context menu to keep it visible in Month. Calendar display settings control the two feeds independently, including per-calendar all-day visibility and the option to hide timed events from Month. The default Adaptive layout keeps consecutive events full width and puts overlapping events side by side. It stretches the time ruler for short events and leaves empty spans at their usual scale. Events crossing an hour boundary remain a single card. Settings → Display → Day view layout also offers Columns, which uses a fixed time ruler.

Quick entry uses local deterministic parsing, with an editable preview and one save action. The final slash selects the calendar, while earlier slashes remain in the title. The user can switch between retrospective logging and scheduling. Explicit calendar names, aliases, manual choices and title rules take precedence over history. A frequently used calendar for an exact title is preselected with an explanation and a dismiss button. The optional default calendar applies after explicit names, rules and history suggestions. It is available in Quick Entry and Calendars settings. The first suggestion uses up to 180 days of non-repeating events; successful Quick Entry saves refine it. An override only changes the current event unless the user chooses to remember it as a rule. History stays on the device and can be turned off in Settings.

In Day, the timeline follows a horizontal drag to reveal the neighboring day at the same clock time, including behind the floating controls. The date updates during the swipe, and short drags snap back. On iOS 18 or later, pull past midnight to fill the ring around the next day's date. At the bottom, the next date and pull hint are already visible. The ring fills as you pull. A haptic marks the release threshold at about 18% of the timeline height, and releasing opens the next day at 00:00. Pull down from the top to open the end of the previous day. The current-time marker draws above event cards. The Tasks strip shows a count and expands from any tap or long press into a scrollable list with Hide Tasks Banner underneath. It collapses when you leave the day, open a sheet, or switch apps. Press and hold the All day banner or a calendar tab to hide it. Settings → Calendar display restores hidden banners and tabs.

Event details show the title, time, calendar and description. Editing the title supports quick-entry syntax with a preview, Apply to event and Keep as title only. Save applies the interpreted title entry while preserving unspecified fields and metadata. Press and hold a writable event for Edit and Delete. On iPhone, Delete opens a bottom sheet with the event and explicit confirmation. Edits save the description to the event’s notes. EventKit saves to system calendars, including configured provider calendars. Save failures keep the draft open. Edits to a stale or missing event ask the user to reopen it. For recurring events, edits and deletion distinguish the current occurrence and future events. System calendar providers manage remote synchronisation.

Calendar events stay in their existing accounts. Settings → Event categories enables named colours for events within the same calendar. Pick a category when adding or editing an event. Stillday stores the tag (for example `[School]`) at the end of the event notes for other calendar apps and displays it separately from the description.

Google Tasks connections show tasks on their scheduled dates, including completed tasks unless hidden in Calendar Display. Completed tasks have a muted icon and strikethrough. Stillday refreshes visible accounts on launch, on returning to Stillday, and every three minutes while a calendar view with tasks is visible. The Connections page shows sign-in and refresh status. Tokens stay in the device Keychain and task results stay in memory. Outlook events use the system calendar account. EventKit doesn't expose Outlook's category names or colours; importing native Outlook categories would require a separate Microsoft Graph integration. TimeTree-only events have no supported outbound sync. An external calendar visible to both apps, or an event copied from TimeTree into that calendar, can appear in Stillday.

Profiles select calendars and Google Tasks connections on this device. Each profile stores its own event calendar picker order. In the profile editor, Calendar Order lets the user drag editable calendars into position. Calendars without a saved position follow the saved order. A source can belong to several profiles. Select one active profile in Settings, or hold the gear and slide down to a profile before releasing. Standard view uses the regular visibility settings. Appearance edits the accent colour for the active view.

Activity options add time before and after an event, with a purpose, optional travel mode and label. The main event keeps its own start and end. Extensions join the main event in one continuous card with a dotted colour strip, and Adaptive view keeps short extension labels readable. Before and After open separate native editor pages. Back returns to the event form; X closes the entire editor without saving. Each defaults to five minutes of walking, with independent duration, purpose and travel-mode defaults under Time Around Event in settings, applied only when adding an extension. Timeline labels show an icon and duration. Extensions use the event background by default, with an optional lighter fill. The optional Blend overlapping before/after time setting is off by default. It lays extensions behind another event and replaces the other event's solid stripe with their dotted colour only over the intersecting portion, leaving that event's fill dominant. Actual core overlaps retain columns. The layout caches a sweep of buffer/core intersections; standalone extension rendering and native event data stay unchanged. Quick entry accepts bare hour numbers and before/after minute clauses in either order, such as `before 11m` or `11m before`. Removable timing chips keep the original input as text when dismissed.

An activity can have linked native copies in several calendars. Matching visible copies draw together, with the active profile determining the primary calendar colour. Group updates validate the native copies and commit the pending changes together. A conflicting copy stays visible and needs review. Users can separate a copy or explicitly delete the whole activity or just one calendar's copy. All timed events use ordinary event cards, including events with display metadata from older builds.

Activity metadata uses an explicitly delimited readable notes footer, with a shared UUID for linked copies. Existing category tags and unrecognised note blocks are preserved. These display details remain readable in other calendar apps.
